## 任务目标

解决"让 LLM 自己判断自己有没有依据"的可靠性问题。**只做轻量两层**（已定范围，不要扩大）：

1. **引用绑定**：回答必须标注引用了哪几条检索证据（【编号】），前端展示来源
2. **answerability 预判**：检索证据不足时，在进 LLM **之前**就拒答，不浪费一次调用也不给模型编造的机会

**明确不做**（用户已定）：二次 LLM 一致性校验（回答生成后再用一个 LLM 核对答案与证据）——不做，避免增加延迟和成本。

## 实现要求

### 第一层：引用绑定

1. `answer.py` 的 prompt 输出格式改为：
   ```json
   {"useful": boolean, "content": "string", "citations": [1, 3]}
   ```
   prompt 里明确要求：content 中的事实必须来自知识条目，citations 列出支撑回答的条目编号（整数数组，无引用时为空数组）
2. `AnswerResult` 加 `citations: list[int]` 字段；解析失败/模型没给 citations 时按空数组兜底，**不要因新增字段导致整体解析失败走兜底回复**
3. citations 越界（编号超出本次知识条数）或无效应过滤掉，别把脏编号透传给前端
4. `chat.py` 把 citations 随 answer JSON 一起落库；**旧消息兼容**：历史消息的 answer JSON 没有 citations 字段，前端渲染要判空
5. 前端 `ChatPage.tsx`：useful=true 且有 citations 时，在气泡下方展示"引用来源"（按编号映射到 chunk 的 heading_path 或 document_title），可点击展开对应知识内容（可复用现有 retrieval-panel 的样式与数据）

### 第二层：answerability 预判

位置：`chat.py` 里 retrieve 之后、调 LLM 之前。

规则（由浅入深，都要做）：

1. **检索结果为空** → 直接拒答，不进 LLM，返回固定话术"暂时不能回答这个问题"，answer 标记 `useful=false`（可加个 reason 字段如 `no_results`，方便日志区分）
2. **最高 rerank 分数低于阈值** → 拒答。阈值进 runtime_config（如 `retrieval.answerability_threshold`，默认 0.6 与 rerank_threshold 对齐；**优先参考阶段 1 基线报告里的 rerank 分数分布来定默认值**，如果报告显示 0.6 砍太狠/太松，按数据调）
3. 注意降级路径：rerank 失败/被 mock 跳过时 `retrieval.rerank_used=false`，此时没有真实 rerank 分数，answerability 阈值判断应跳过（沿用现有行为），只做"空结果拒答"
4. 拒答要写进链路 trace（chat.py 的节点机制，参考 `docs/pipeline-nodes.md`），让调试页能看到"该次请求在 answerability 处被拦截"

### 改动前后对比（本阶段的核心验收依据）

用阶段 1 的评测脚本（`backend/eval/`，含 LLM 裁判）复跑：

- **Faithfulness（忠实度）**：应上升——这是防幻觉改动的直接目标指标
- **Answer Relevance（答案相关性）**：不下降（或下降 <5 个百分点），证明拒答收紧没有误伤正常回答
- **unanswerable 题的拒答正确率**：应明显上升
- 把对比结果追加到 `docs/eval/` 下的报告里（新增一节"阶段 2 改动前后对比"）；通过后更新 `thresholds.json` 的 CI 阈值，守住新水位

## 坑清单

1. **answer.py 的 prompt 模板用三个 `%s` 顺序 replace 插值**（`build_answer_prompt`），改模板时保持"知识→历史→消息"顺序，且注意 Python `%` 与 str.replace 的差异——这里是 replace 不是 format，字面 `%` 不会炸，但顺序换了内容就串了
2. **messages 表里存的是 answer JSON 字符串**，加字段是向后兼容的（旧数据少字段），但**不要改旧数据**，读取时判空即可
3. **runtime_config 加新参数**要仿照 `runtime_config.py` 里 ParamDef 的写法（key/label/type/default/min/max/分组），加完默认即热生效，调试页自动展示
4. **拒答话术保持一致**："暂时不能回答这个问题"是全系统统一兜底话术（answer.py `_FALLBACK_REPLY`），别另造一个
5. DeepSeek json_mode 偶尔输出带 markdown 代码块包裹的 JSON——`_extract_json` 已处理，新增字段走同一解析路径
