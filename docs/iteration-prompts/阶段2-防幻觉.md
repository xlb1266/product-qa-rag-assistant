# 阶段 2：回答防幻觉（引用绑定 + answerability 预判）

请在当前 RAG 客服项目中为回答生成环节增加防幻觉机制。当前回答链路的可靠性短板是"让模型自己判断自己有没有依据"：prompt 把检索到的知识按【1】【2】编号填入（`app/core/answer.py`），却只要求模型输出 `{useful, content}`——既不要求标注引用了哪几条，检索空手或全是低分结果时也照样进 LLM，指望它自觉说 useful=false。本次做轻量两层防护（已定范围，不扩大）：

- **引用绑定**：回答必须标注引用了哪几条检索证据（【编号】），前端展示来源，让每个事实可溯源。
- **answerability 预判**：检索证据不足时在进 LLM 之前直接拒答，不给模型编造的机会，也省一次调用。
- **明确不做**二次 LLM 一致性校验（回答生成后再用裁判模型核对答案与证据），避免增加延迟与成本。

引用绑定的实现要求：

- prompt 输出格式扩展为 `{"useful": boolean, "content": "string", "citations": [1, 3]}`，明确要求 content 中的事实必须来自知识条目，citations 列出支撑回答的条目编号（整数数组，无引用时为空数组）。
- AnswerResult 增加 citations 字段；解析失败或模型未返回 citations 时按空数组兜底，不得因新增字段导致整体解析失败而走兜底回复。
- citations 越界（编号超出本次知识条数）或无效必须过滤，不得把脏编号透传给前端。
- `chat.py` 将 citations 随 answer JSON 一起落库；历史消息的 answer JSON 没有该字段，前后端读取一律判空兼容，不迁移旧数据。
- 前端聊天页：useful=true 且有 citations 时，在气泡下方展示"引用来源"（编号映射到 chunk 的 heading_path 或 document_title），可展开对应知识内容；样式可复用现有知识库参考面板。

answerability 预判的实现要求：

- 位置在 `chat.py` 的 retrieve 之后、调用 LLM 之前，两条规则都要落地：检索结果为空 → 直接拒答不进 LLM；检索非空但最高 rerank 分数低于阈值 → 拒答。
- 阈值进 runtime_config（如 `retrieval.answerability_threshold`），默认值优先参考评测基线报告（docs/eval/）里的 rerank 分数分布来定，不凭空拍；rerank 失败或 mock 降级（rerank_used=false）时跳过分数判断，只保留空结果拒答。
- 拒答统一使用全系统兜底话术"暂时不能回答这个问题"；拦截事件写入链路 trace（新增 answerability 节点，命名遵循 docs/pipeline-nodes.md），调试页可见该请求在何处被拦。
- 拒答不进 LLM，但要正常落库、正常返回响应，保证链路完整。

已知约束：

- answer.py 的 prompt 模板用三个 `%s` 顺序 replace 插值（知识→历史→消息），改模板时保持顺序不变。
- runtime_config 新增参数按 ParamDef 现有写法（key/label/type/default/min/max/分组），保存即热生效、调试页自动展示。
- DeepSeek json_mode 偶尔用 markdown 代码块包裹 JSON，现有 `_extract_json` 已处理，新字段走同一解析路径。

验收依据（核心）：用 `backend/eval/` 评测脚本（含 LLM 裁判）复跑——Faithfulness 应上升（防幻觉改动的直接目标指标），Answer Relevance 不下降（降幅 <5 个百分点，证明拒答收紧没有误伤正常回答），unanswerable 题拒答正确率明显上升。结果追加到 docs/eval/ 报告"阶段 2 改动前后对比"一节，并更新 thresholds.json 的 CI 阈值守住新水位。

Git 提交要求：每完成一个可独立验证的改动单元（answer.py 引用绑定 / chat.py answerability 预判 / 前端引用展示 / 评测对比与阈值更新）做一次提交，提交信息用中文、说清楚改了什么和为什么；全部完成后 `git status` 工作区必须干净。

全部完成后先自查上述要求是否逐条满足，再主动询问用户是否手动验收（附建议验收步骤：问一个知识库外的问题确认秒拒且调试页显示未进 LLM、问一个正常问题看引用来源展示、复跑评测看三个指标变化），确认通过才算本阶段结束。
